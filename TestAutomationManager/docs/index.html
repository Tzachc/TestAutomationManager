What is Test Automation Manager?

A comprehensive platform for managing your test automation infrastructure

Test Automation Manager is a sophisticated desktop application built with WPF and .NET 8.0 that provides centralized management for your Selenium-based test automation infrastructure.

Multi-Schema Support

Work with multiple database schemas seamlessly, switch between PRODUCTION and DEV environments.

Complete Audit Trail

Track every change with detailed history logging. Know who changed what and when.

Real-time Sync

Database changes are monitored and synced automatically across your application.

Modern UI

Beautiful dark theme with Material Design components for a premium user experience.

Behind the Scenes: Data Model

Here's how tests are stored in the database:

public class Test { public int TestID { get; set; } public string TestName { get; set; } public string RunStatus { get; set; } // "Passed", "Failed", "Running" public bool IsActive { get; set; } public string? Bugs { get; set; } public string? Email { get; set; } public string? ExceptionMessage { get; set; } public DateTime? LastRun { get; set; } public DateTime? LastPass { get; set; } // Navigation properties for hierarchical data public List<Process> Processes { get; set; } }

SQL Query Example

Here's how we retrieve test data with statistics:

SELECT t.TestID, t.TestName, t.RunStatus, t.IsActive, COUNT(p.ProcessID) AS ProcessCount, t.LastRun, t.LastPass, DATEDIFF(day, t.LastPass, GETDATE()) AS DaysSinceLastPass FROM Tests t LEFT JOIN Processes p ON t.TestID = p.TestID WHERE t.IsActive = 1 GROUP BY t.TestID, t.TestName, t.RunStatus, t.IsActive, t.LastRun, t.LastPass ORDER BY t.LastRun DESC
Pro Tip: Test Statistics

The application calculates real-time statistics using efficient LINQ queries:

// Real-time statistics calculation var stats = new { Active = tests.Count(t => t.IsActive), Passed = tests.Count(t => t.RunStatus == "Passed"), Failed = tests.Count(t => t.RunStatus == "Failed"), Running = tests.Count(t => t.RunStatus == "Running") }; // Update UI with statistics ActiveCountText = $"Active: {stats.Active}"; PassedCountText = $"Passed: {stats.Passed}";

Process Management

Define and manage automation workflows

Overview

Processes are the automation workflows that execute within your tests. Each process contains a sequence of functions and can be configured with parameters for flexible execution.

Key Capabilities

  • Create and edit processes with detailed metadata
  • Set execution order and position
  • Configure process parameters for dynamic behavior
  • Copy and paste processes for rapid duplication (Ctrl+C, Ctrl+V)
  • Navigate parameters using up/down arrow keys
  • View and modify process comments and descriptions
  • Delete processes with confirmation dialog
  • Inline editing for quick updates

Process Properties

Property Description Example
ProcessID Unique process identifier 1001
ProcessName Descriptive name for the process "Login Flow"
Module Module or category grouping "Authentication"
Position Execution order within test 1, 2, 3...
Param Process parameters "username=admin"
Comments Additional notes and documentation "Handles login retry logic"
TestID Parent test identifier 500

Common Operations

Create Process

Click "Add Process" button to create a new automation workflow.

Edit Details

Double-click any field to modify process properties inline.

Duplicate Process

Select a process and press Ctrl+C then Ctrl+V to duplicate.

Change Order

Edit the Position field to change execution order.

Process Execution Flow

Here's how processes are executed in sequence:

// Load all processes for a test, ordered by Position var processes = await _repository .GetProcessesForTest(testId) .OrderBy(p => p.Position) .ToListAsync(); // Execute each process sequentially foreach (var process in processes) { Console.WriteLine($"Executing: {process.ProcessName}"); // Get all functions for this process var functions = process.Functions .OrderBy(f => f.Position) .ToList(); // Execute each function foreach (var function in functions) { await ExecuteFunction(function); } }
Important: Process Order Matters!

Processes execute in ascending order based on the Position field. Make sure your processes are numbered correctly: 1, 2, 3, etc.

Real-World Example: Login Process

Here's a typical login process configuration:

Overview

Functions are the building blocks of your automation processes. Each function represents a discrete action or operation with configurable operators and parameters.

Function Configuration

Operator Web3 operator type Click, SendKeys, Wait, etc.
Position Execution order in process 1, 2, 3...
Param Function parameters Element locators, values
Pass Success condition Expected result for pass
Fail Failure condition Expected result for fail

Working with Functions

  • Create functions within processes
  • Set operators for Web3 automation
  • Configure pass/fail conditions
  • Use temporary parameters (tempParam1 through tempParam11111)
  • Edit functions inline for quick updates
  • Organize functions by module
  • Set execution position within process
Temporary Parameters: Functions support temporary parameters from tempParam1 to tempParam11111 for storing and passing data during test execution.

Database Backups

Protect your data with comprehensive backup management

Overview

The Backups module provides comprehensive database backup and restore capabilities. Create snapshots of your database, browse backup history, and safely work with backup copies in preview mode.

Key Features

  • View Backup History: Browse all database backups with creation dates and file sizes
  • Create Backups: Generate new database snapshots on demand
  • Restore from Backup: Roll back to previous database states
  • Preview Mode: Work with backup copies without affecting production data
  • Multiple Schemas: Backup support for all configured database schemas
  • Backup Information: View detailed metadata including size and timestamp

Working with Backups

1. Create Backup

Click the "Create Backup" button to generate a new database snapshot. The system will create a backup with a timestamp.

Format: DatabaseName_YYYY-MM-DD_HH-MM-SS.bak
2. Browse Backups

View all available backups in a chronological list. Each entry shows:

  • Backup name
  • Creation date and time
  • File size
  • Restore status
3. Preview Mode

Click "Preview" to create a temporary copy of the backup and work with it safely. The window title will show "[PREVIEW]" indicator.

Preview mode creates a temporary database that won't affect your production data.
4. Restore Backup

Select a backup and click "Restore" to roll back your database to that point in time.

Warning: Restoring will overwrite your current database. Create a backup first!

Backup Information

Each backup entry displays comprehensive information:

Property Description
Name Backup file name with timestamp
CreationDate When the backup was created
Size Backup file size in MB/GB
Status Current status (Available, Restoring, etc.)

Backup Best Practices

Regular Backups

Create backups before major changes or test runs to ensure you can roll back if needed.

Use Preview Mode

Always use preview mode when testing changes. This protects your production data.

Naming Convention

Backups are automatically named with timestamps, making it easy to identify when they were created.

Check Preview Indicator

When in preview mode, the window title shows "[PREVIEW]" to remind you that you're working with a copy.

Pro Tip: Exit preview mode to return to production database. The preview copy is automatically cleaned up.
Important: Restore operations cannot be undone. Always backup current state first!
